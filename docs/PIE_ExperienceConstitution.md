# PIE Experience Constitution

## Rule

PIE is the intelligence. The app is the simplest possible interface to PIE.

The user should not see PIE's complexity. The user should experience guidance.

## Principles

1. One screen, one purpose.
2. One dominant primary action.
3. PIE leads; the user verifies.
4. The user should not search for workflows.
5. The user should not configure daily workflows.
6. PIE asks only for the minimum evidence needed.
7. Every interaction should reduce uncertainty.
8. Advanced tools live under More.
9. Never expose internal cognitive models to normal users.
10. The interface should become simpler as PIE becomes smarter.

## Primary Navigation

Primary navigation is:

- PIE
- Capture
- Review
- More

Today/Home becomes PIE. Walk becomes Capture. Reports and review workflows remain Review. Projects, Schedule, Documents, History, Settings, Admin, Diagnostics, and Developer Tools live under More.

## More

More contains secondary workflows:

- Projects
- Schedule
- Documents
- History
- Settings
- Admin
- Developer Tools

Developer and diagnostic items must be clearly separated from normal user workflows.

## Product Test

Every interaction should reduce uncertainty, preserve review, and make the next action obvious.
