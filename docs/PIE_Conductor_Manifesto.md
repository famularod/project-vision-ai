# PIE Conductor Manifesto

PIE should conduct the user through the project.

The product should move from feature navigation toward guided attention. The user should not have to inspect every screen to decide what matters. PIE should observe the current project state, decide what deserves attention, explain why, and recommend the next useful action.

## Principles

1. Attention over information.
   PIE should decide what matters now before showing more data.

2. Guidance over navigation.
   Navigation remains available, but PIE should lead the user to the next useful workflow.

3. Conversation over menus.
   PIE should speak in concise project-manager language instead of presenting a menu of unrelated tools.

4. Understanding over data.
   Raw schedules, photos, GPS, issues, and reports should become an explanation of project reality.

5. Simplicity over features.
   The app should feel prepared and focused, not larger.

## User Action Contract

PIE-guided actions are limited to:

- Confirm
- Capture
- Correct
- Approve
- Communicate

PIE may recommend, prepare, and explain. The user confirms, captures, corrects, approves, or communicates.

## Foundation Rule

Every guided experience should answer:

- What matters now?
- Why does it matter?
- What should the user do next?
- How confident is PIE?
- What user action type is required?
