## Priority 2 — biggest structural wins

**4. App.tsx grew 28% instead of shrinking.** 18,317 → 23,511 lines on this branch. The new DAVE capture features correctly landed as separate components (`DAVEVoiceCaptureSheet`, etc.), but all their wiring, state (65 `useState`, 47 `useEffect`), and ~70 inline components still landed inside App.tsx. The refactor direction is right; the discipline of "new features must not grow App.tsx" isn't holding. Suggested rule going forward: any new feature ships as a module plus a small wiring block, and each PR that touches App.tsx should leave it no bigger than it found it.

**5. A second dead-code pass is ready to harvest: ~16,000 lines.** Verified by transitive import analysis from the app's real entry points, 66 files are unreachable, including 49 components (8,700 lines, e.g. `HomeDashboard`, the whole KPI/Weekly-Report card family), 5 screens (~6,000 lines: `ProjectAssistantScreen`, `ProjectOverviewScreen`, `ScheduleScreen`, `BuildUpdateScreen`, `DiagnosticsScreen`), 4 hooks, and 5 services. Git history preserves everything, so deletion is safe and makes every future search and AI session cheaper and less error-prone. Also delete the tracked junk file `package copy.json`.

**6. Duplicate type systems are still live.** App.tsx defines its own `UpdatePhoto`, `ProjectUpdate`, `ProjectArea`, `ScheduleItem` while `types/index.ts` exports parallel versions used by services. This is the known drift risk from CLAUDE.md and the Codex branch didn't close it. Unifying on `types/index.ts` is a mechanical, typecheck-guarded change and a good next slice.

## Priority 3 — worth doing, not urgent

**7. The PIE intelligence layer is very large for what ships.** ~40 `PIE*` services (PIERuntime alone is 5,219 lines) totaling a large share of the 127k-line codebase. All reachable, but complexity here is the main long-term maintenance cost for a single-user app. Recommendation: freeze this layer (no new engines), and when touching one, check whether its output actually reaches the screen.

**8. Edge function cost guard.** `dave-transcribe-memory` verifies the caller is logged in but not that they're the app owner (`dave_is_app_owner`). With one account this is theoretical, but any future second account could burn your OpenAI credits. One-line check to add next time that function is touched anyway.

**9. Test coverage is a foundation, not coverage.** The 14 tests cover navigation, report selection, and schedule reconciliation. The riskiest code — SyncService's queue/conflict logic and photo-path handling — has exported pure functions (`markMissingPhotosUnavailable`, `projectUpdateWithCloudPhotoPaths`, conflict normalizers) that are ideal, cheap test targets. Adding tests there pays for itself the next sync bug.
